# 人生ゲーム（仮）— ゲーム仕様書

山本彩「game」（アルバム『Narrative』2026/10/28）にちなんだブラウザゲーム。
「生まれた瞬間から始まる人生ゲーム」をテーマに、ガチャで決まった才能や環境のまま、縦にどこまでも登っていくエンドレスのローグライトアクション。

> **【提案】** と付いた項目は、ヒアリングで決めていない細部を仮に埋めたもの。実装前に見直す。

---

## 1. 決定事項（ヒアリング結果）

| 項目 | 決定 |
|---|---|
| ジャンル | ローグライトの縦スクロールジャンプアクション（エンドレス） |
| プレイ時間 | 1回 1〜3分 |
| 対象環境 | スマホ優先（片手・縦画面）。PCでも遊べる |
| トーン | コミカル全振り |
| 操作 | 画面の左右タップで、その側の上の段へジャンプ |
| 生まれガチャ | 才能・難易度・家庭環境・見た目（すべて） |
| スコア | 人生ポイント（年齢・実績・レアイベントの合計） |
| リセット | 周回で解放（最初はリセットできない） |
| 障害 | バグ足場・ルート消失・人生イベントの敵・迫りくる時間 |
| 終わり方 | エンドレス（倒れたら終了） |
| サーバー機能 | ランキング・ガチャ排出率の統計・唯一無二の称号・他人の人生の跡（墓標） |
| ビジュアル | ドット絵 |
| プレイヤー名 | 自由入力 |
| データ保存 | Cloudflare D1（SQLite） |
| 言語 | 日本語のみ |
| 楽曲 | Apple Music 公式埋め込みプレイヤーをゲーム画面の下に置く（ゲームとは連動しない） |
| 歌詞 | ゲーム画面には出さない |

### 権利に関するルール
- 歌詞の文章はゲーム内のテキスト・画像・ソースコードに**そのまま使わない**。モチーフを言い換えたオリジナルの文章にする。
- 楽曲の音源はホストしない。曲は Apple Music の公式埋め込み（`embed.music.apple.com`）だけで流す。
- ゲーム内の効果音とBGMは自作する（コードで生成するチップチューン）。

## 2. ゲームの流れ

```
タイトル
  └→ 名前入力（初回のみ。以降は端末に保存し、変更もできる）
       └→ 生まれガチャ演出（才能3つ・難易度・家庭環境・見た目）
            └→ プレイ（0歳からスタート）
                 └→ ゲームオーバー（享年・死因・人生ポイント）
                      └→ リザルト（ランキング順位・排出率・称号）
                           └→ 「もう一度生まれる」→ 生まれガチャへ
```

## 3. 操作

| 入力 | 動作 |
|---|---|
| 画面の左半分をタップ / ←キー / Aキー | 左上の段へジャンプ |
| 画面の右半分をタップ / →キー / Dキー | 右上の段へジャンプ |
| リセットボタン（解放後） / Rキー | リセット再起動（§7） |
| 一時停止ボタン / Escキー | ポーズメニュー |

- 段は2列（左・右）のジグザグ構造。1回タップすると1段上がる。
- 連打で速く登れる。入力は先行入力を1つまで受け付ける。
- 画面は縦長の論理解像度 270×480 ドットで描き、ウィンドウに合わせて拡大する。

## 4. 年齢と人生ステージ

- 登った段数が年齢になる。**【提案】** 5段で1歳（1段＝0.2歳）。2分で40〜60歳くらいに届く想定。
- 年代ごとに背景・敵・BGMが変わる。エンドレスなので100歳を過ぎても続き、おかしな年代になっていく。

| 年齢 | ステージ【提案】 | 主な敵・イベント【提案】 |
|---|---|---|
| 0〜5 | 幼少期 | おもちゃ、苦い野菜 |
| 6〜17 | 学生 | 宿題、テスト、受験 |
| 18〜21 | 青春 | 単位、バイトのシフト |
| 22〜64 | 社会人 | 上司、締め切り、請求書、満員電車 |
| 65〜99 | 老後 | 年金の通知、腰痛 |
| 100〜199 | 仙人 | 霞、雲 |
| 200〜999 | 妖怪 | お札、陰陽師 |
| 1000〜 | 神話 | 隕石、ビッグバン |

## 5. 生まれガチャ

ゲーム開始時に自動で引く。自分では選べない。結果はレアリティ（N / R / SR / SSR）付きで派手に演出する。

### 5.1 才能（3つ引く）【提案】

| 才能 | レア | 効果 |
|---|---|---|
| 2段ジャンプ | SR | 1回のタップで2段上がることがある |
| 強心臓 | SR | ライフ+1 |
| 磁石 | R | 近くの実績アイテムを引き寄せる |
| 早起き | R | 「時間」がせり上がる速度が10%遅い |
| バグ耐性 | R | バグ足場を1回だけ無効にする |
| 先読み | SR | 3段先のルート消失が見える |
| 強運 | SSR | レアイベントが起きやすい |
| 腕立て伏せが速い | N | 効果なし |
| 声が大きい | N | 効果なし（ジャンプの効果音が大きくなる） |
| 方向音痴 | N（ハズレ） | ときどき左右が入れ替わる |
| 寝坊 | N（ハズレ） | 開始時に「時間」がすぐ下にいる |

- 才能は全部で20種類を目標にする（唯一無二の判定に組み合わせの数が必要なため。§9.3）。

### 5.2 難易度

| 難易度 | 排出率【提案】 | 内容 |
|---|---|---|
| EASY | 15% | ライフ+1、敵が少ない。ポイント×0.8 |
| NORMAL | 40% | 基準。ポイント×1.0 |
| HARD | 30% | 敵が多く「時間」が速い。ポイント×1.3 |
| VERY HARD | 12% | ポイント×1.6 |
| LUNATIC | 3% | バグ足場だらけ。ポイント×2.0 |

画面には「この難易度は選んでいません」と注記を出す。

### 5.3 家庭環境【提案】

| 家庭環境 | 効果 |
|---|---|
| 実家が太い | 開始時に実績1つを持っている |
| 放任主義 | 「時間」が15%速いが、人生ポイント+20% |
| 過保護 | 最初の20歳までは1回だけミスしても助かる |
| 転勤族 | ステージの背景がバラバラに入れ替わる |
| ごく普通 | 効果なし（「普通が一番」と表示） |
| 大家族 | 敵が出たとき、ときどき家族がかばってくれる |

### 5.4 見た目
髪型・帽子・服の色をランダムに組み合わせる。性能には影響しない。

## 6. 障害とミス

### 6.1 ライフ
- 基本は**ライフ1**（1回のミスが命取り）。才能・難易度・家庭環境で増える。
- 0〜3歳（15段目まで）は両側に必ず足場がある。最初の数タップで即ゲームオーバーにならないようにするため。
- 足場のない側をタップすると、キャラが下に落ちる演出が入る（生き残った場合は元の段に戻る）。
- ミスするとライフが1減り、少しの間無敵になる。ライフが0になるとゲームオーバー。

### 6.2 障害

| 障害 | 内容 |
|---|---|
| バグ足場 | 見た目が乱れている足場。乗ると、すり抜けて落ちる・左右が反転する・数段ワープする、のどれかが起きる。エラーメッセージ風の演出（例：「ERR: 人生.exe は応答していません」） |
| ルート消失 | 何段か続けて片側にしか足場がない区間。足場のない側をタップすると落ちてミス |
| 人生イベントの敵 | 年代ごとの敵（§4）が横から飛んでくる。当たるとミス |
| 迫りくる時間 | 画面の下から「時間」（砂時計の波）がせり上がってくる。止まっていると追いつかれてゲームオーバー（ライフに関係なく即終了）。年齢とともに速くなる |

### 6.3 死因
ゲームオーバーの原因をコミカルな文章で出す。【提案】例：
- 時間に追いつかれた →「のんびりしすぎた」
- 上司に当たった →「上司に捕まった」
- バグ足場で落ちた →「仕様です」

## 7. リセット再起動（周回で解放）

- 1〜2回目は、リセットボタンを押しても「この機能は解放されていません」と出るだけ。
- **【提案】** 通算3回目のプレイから、1プレイに1回だけ「リセット再起動」が使える。
  - 使うと画面にノイズが走って再起動演出が入り、3秒前の状態に戻る（ライフ・年齢・敵の位置）。
  - 通算10回目で、1プレイ2回に増える。
- 解放したときに、前向きなメッセージを出す（例：「リセットは、上手く使えばいい」）。
- 通算プレイ回数は端末の localStorage に保存する（サーバーには送らない）。

## 8. 人生ポイント（スコア）

**【提案】**

```
人生ポイント = (到達年齢 × 100 + 実績 × 500 + レアイベント点) × 難易度倍率
```

- **実績**：道中に落ちているアイテム（卒業証書・昇進・資格・宝くじなど）。年代ごとに種類が変わる。
- **レアイベント**：ごくまれに起きる（例：「宝くじが当たった」「タイムマシンを拾った」）。1つで1000〜5000点。
- 小数点以下は切り捨て。

## 9. サーバー機能（Cloudflare Workers + D1）

### 9.1 ランキング
- 人生ポイントの上位を表示する（全期間・今日）。
- 名前・ポイント・享年・難易度・才能を表示する。

### 9.2 ガチャ排出率の統計
- 引いた才能・難易度・家庭環境が、全プレイヤーのうち何%かを表示する。
  例：「才能『腕立て伏せが速い』は全プレイヤーの3.2%が持っています」

### 9.3 唯一無二の称号
- 才能3つ・難易度・家庭環境の組み合わせが、これまで誰も引いていないものなら「唯一無二」の称号を付ける。
- 判定キーは、才能IDを並べ替えて難易度・家庭環境とつなげた文字列。
- 見た目は判定に含めない。**【提案】** 才能20種なら組み合わせは 1,140 × 5 × 6 = 34,200 通り。

### 9.4 他人の人生の跡（墓標）
- 他のプレイヤーがゲームオーバーになった年齢の高さに、墓標を立てる。
- 墓標には「○○さん 享年37歳（上司に捕まった）」のように表示する。
- 毎回ステージは違うので、位置は「年齢（高さ）」だけで合わせる。左右どちらの列に立てるかはランダム。
- **【提案】** 1画面に出す墓標は最大3つまで。最近のものを優先する。

### 9.5 プレイヤー名（自由入力）
- 1〜10文字。文字（漢字・かな・英字）・数字・一部の記号が使える。名前の入力はゲーム外の HTML ダイアログで行う（スマホでキーボードを出すため）。
- NGワードはサーバー側で判定する。引っかかった場合は「名無しの人生」に置き換えて保存する。
- 名前は端末に保存し、次回から入力を省く。

### 9.6 API【提案】

| メソッド | パス | 内容 |
|---|---|---|
| POST | `/api/runs` | プレイ結果を送る。順位・排出率・唯一無二かどうかを返す |
| GET | `/api/ranking?period=all\|today` | ランキングの上位20件 |
| GET | `/api/graves?from=0&to=120` | 指定した年齢の範囲にある墓標 |
| GET | `/api/stats` | ガチャ排出率の統計 |

`POST /api/runs` で送る内容：

```json
{
  "name": "ちくわぶ",
  "points": 48200,
  "age": 47.4,
  "achievements": 5,
  "difficulty": "HARD",
  "family": "rich",
  "talents": ["double_jump", "magnet", "pushup"],
  "look": "hat03-red",
  "cause": "boss",
  "runCount": 4
}
```

### 9.7 D1 テーブル【提案】

```sql
CREATE TABLE runs (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  name         TEXT    NOT NULL,
  points       INTEGER NOT NULL,
  age          REAL    NOT NULL,
  achievements INTEGER NOT NULL,
  difficulty   TEXT    NOT NULL,
  family       TEXT    NOT NULL,
  talents      TEXT    NOT NULL,  -- 並べ替えた才能IDをカンマ区切り
  combo_key    TEXT    NOT NULL,  -- 唯一無二の判定用
  look         TEXT    NOT NULL,
  cause        TEXT    NOT NULL,
  created_at   INTEGER NOT NULL   -- UNIX秒
);
CREATE INDEX idx_runs_points ON runs(points DESC);
CREATE INDEX idx_runs_created ON runs(created_at);
CREATE INDEX idx_runs_combo ON runs(combo_key);
CREATE INDEX idx_runs_age ON runs(age);
```

### 9.8 不正対策
- 値の範囲チェック（年齢やポイントの上限、プレイ時間に対して年齢が高すぎないか）だけを行う。
- 本格的なチート対策はしない（カジュアルなファンゲームのため）。**【提案】** 同じIPからの送信は1分に5回まで。

## 11. 技術構成

### 11.1 構成

| 部分 | 技術 |
|---|---|
| ゲーム本体 | Go + Ebitengine v2.10（`GOOS=js GOARCH=wasm` でビルド） |
| サーバー | Go + `github.com/syumai/workers-go`（Cloudflare Workers） |
| 配信 | Workers Static Assets（`public/` に index.html・game.wasm・wasm_exec.js） |
| データ | Cloudflare D1 |
| 開発・デプロイ | wrangler |

- `github.com/syumai/workers` は `github.com/syumai/workers-go` に移管され、旧モジュールは転送用だけになっている。そのため後継の `workers-go` を使う。
- Ebitengine は TinyGo に対応していないので、ゲームは標準の Go でビルドする。Worker も標準の Go でビルドする（容量が問題になったら TinyGo を検討する）。

### 11.2 素材
- **ドット絵**：コードで描くか、自作の小さなPNGを `go:embed` で埋め込む。
- **日本語ドットフォント**：`github.com/hajimehoshi/bitmapfont/v4`（12px、JIS の漢字を収録、Apache 2.0 ほか）。漢字の名前もそのまま表示できる。
- **効果音・BGM**：コードで合成するチップチューン。

### 11.3 ディレクトリ構成【提案】

```
/
├── docs/SPEC.md
├── game/          # Ebitengine のゲーム本体（wasm）
├── worker/        # workers-go の API サーバー
├── migrations/    # D1 のマイグレーション
├── public/        # 配信ファイル（index.html など）
├── wrangler.jsonc
├── Makefile
└── go.mod
```

---

### 11.4 実装時の判断
- ゲームの wasm は Workers Static Assets の1ファイル上限（25MiB）以内に収める必要がある。wasm 版では `net/http` を使わずブラウザの `fetch` を直接呼び、約26.6MB → 約18.7MB に減らした。
- Apple Music の埋め込みとゲームを分けるため、`index.html`（外側のページ）の中に `game.html`（ゲーム本体）を iframe で読み込む。
